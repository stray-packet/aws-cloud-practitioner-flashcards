# Day 1 — reviewed knowledge

This note consolidates seven Gemini reports from the same study day. Repeated material was merged, exam-relevant distinctions were preserved, and overly absolute or misleading statements were corrected before card generation.

## Exam alignment

CLF-C02 has four scored domains: Cloud Concepts; Security and Compliance; Cloud Technology and Services; and Billing, Pricing, and Support. This study day is broad and especially strong in technology/services, networking, infrastructure, and foundational security. Historical launch dates, the informal CSP tier taxonomy, Gartner market positioning, Jevons paradox, and career commentary are useful context but are not treated as priority exam facts.

## Cloud foundations and service models

- Cloud infrastructure is commonly understood through compute, networking, storage, and database capabilities. These are a learning framework, not an official list of four AWS pillars.
- Infrastructure as a Service (IaaS) provides virtualized infrastructure while the customer retains control over operating systems, applications, data, and many configurations.
- Cloud resources are API-driven. The AWS Management Console, AWS CLI, SDKs, and infrastructure-as-code tools ultimately invoke AWS service APIs. “Single Unified API” is useful as a mental model, not the name of an AWS product or a literal single endpoint.
- Infrastructure as Code (IaC) makes infrastructure repeatable, reviewable, and automatable through version-controlled definitions.
- Terraform is a multi-provider IaC tool that uses HCL. It creates an execution plan and calls provider APIs; it is not a compiler that creates an application binary.
- Public cloud providers, VPS providers, colocation facilities, hypervisors, and private-cloud management platforms occupy different layers. The Tier 1–4 scheme discussed in the source is informal and should not be memorized as AWS exam terminology.
- OpenStack and Apache CloudStack are cloud-management platforms. VMware vSphere is a virtualization platform. They are not “Tier 4 cloud providers.” Colocation providers supply facility space, power, cooling, connectivity, and physical security for customer-owned equipment.
- Bare metal, virtual machines, containers, and serverless computing progressively abstract infrastructure management. Containers share a host operating-system kernel, whereas virtual machines include guest operating systems on virtualized hardware.

## Early services and core service selection

- Amazon SQS is a managed message queue used for asynchronous communication and decoupling. Producers place messages in a queue and consumers process them independently.
- Amazon SNS is a publish/subscribe service used for fan-out to multiple subscribers, including application endpoints and human-facing channels.
- Queueing and pub/sub solve different delivery patterns: SQS retains messages for consumers to poll and process; SNS pushes each publication to subscribed endpoints.
- Amazon EC2 provides resizable virtual compute instances with customer control of the guest operating system and software stack.
- Amazon RDS is a managed relational database service. AWS manages more of the database platform, while the customer still manages data, access, schema, configuration choices, and application behavior.
- Amazon SimpleDB is a legacy non-relational service and historical context for AWS databases. Its launch history is not a CLF-C02 priority.

## Global infrastructure

- An AWS Region is a separate geographic area that contains multiple isolated Availability Zones.
- An Availability Zone (AZ) consists of one or more discrete data centers with redundant power, networking, and connectivity. Multi-AZ designs reduce exposure to a single-AZ failure.
- A VPC is regional and can span the Availability Zones of its Region.
- A subnet belongs to exactly one Availability Zone. An AZ can contain multiple subnets.
- AZ letter mappings such as `us-east-1a` can differ between AWS accounts; AZ IDs provide consistent physical-zone identifiers across accounts.
- A Region is selected based on latency, regulatory requirements, service availability, resilience design, and price.
- Edge locations bring content and network entry points closer to users. Amazon CloudFront uses edge locations and regional edge caches to deliver content.
- S3 buckets are created in a Region even though bucket names are globally unique within the general-purpose bucket namespace and the console offers a cross-Region view.
- IAM is treated as a global service for exam purposes; IAM identities and policies are not recreated independently in every Region.

## VPCs, subnets, and network security

- A VPC is a logically isolated virtual network with address ranges, route tables, subnets, gateways, and security controls.
- A public subnet has a route to an internet gateway. A resource also needs an appropriate public address and security rules to communicate directly with the internet; placement in a public subnet alone does not make it reachable.
- A private subnet has no direct route to an internet gateway. Outbound connectivity can be provided through services such as a NAT gateway, or private service access can be provided through VPC endpoints.
- Security groups are stateful, apply at the resource network-interface level, contain allow rules only, and automatically permit response traffic for an allowed flow.
- Network ACLs apply at subnet boundaries, are stateless, support allow and deny rules, and evaluate numbered rules in ascending order until a match is found.
- Security groups are the primary fine-grained control. Network ACLs can add coarse-grained, defense-in-depth controls such as denying a particular IP range for a subnet.
- Amazon S3 is a managed service outside the customer VPC; a bucket is not placed in a subnet.

## VPC endpoints and hybrid connectivity

- A VPC endpoint allows private connectivity from a VPC to supported services without requiring an internet gateway, NAT device, VPN connection, or public IP on the client resource.
- A gateway endpoint adds service routes to selected route tables. Gateway endpoints support Amazon S3 and DynamoDB and have no additional endpoint charge.
- An interface endpoint creates elastic network interfaces with private IP addresses, is powered by AWS PrivateLink, can use security groups, and normally incurs endpoint-hour and data-processing charges.
- S3 and DynamoDB can also support interface endpoints; therefore “always use a gateway endpoint” is too absolute. For ordinary same-Region VPC access, a gateway endpoint is usually the simpler no-additional-charge choice.
- AWS Direct Connect is a dedicated network connection between a customer location and AWS. It is chosen for predictable private connectivity, bandwidth, and hybrid requirements; it is not required merely to benefit from the AWS global network.
- A Site-to-Site VPN was mentioned only as an adjacent alternative and was not studied in detail.

## Content delivery and network acceleration

- Amazon CloudFront is a content delivery network that caches HTTP/HTTPS content at edge locations. Origins can include S3, load balancers, EC2-hosted applications, and custom HTTP origins.
- Cache invalidation removes selected cached objects before their normal expiration. AWS WAF can be associated with CloudFront to filter web requests.
- AWS Global Accelerator improves availability and performance for supported TCP and UDP applications by routing traffic through the AWS global network. It does not cache content.
- For IPv4 accelerators, Global Accelerator supplies two static anycast IPv4 addresses by default. Exact address behavior differs for dual-stack configurations.
- S3 Transfer Acceleration speeds long-distance transfers to and from an S3 bucket by using AWS edge infrastructure and optimized network paths.
- Regional edge caches are larger intermediate CloudFront cache layers between many edge locations and origins. “Point of Presence” is a broad networking term and should not be treated as a separate AWS service.

## Edge, on-premises, and regulated infrastructure

- AWS Local Zones place selected AWS infrastructure closer to a metro area and connect back to a parent Region. They address latency-sensitive local workloads.
- AWS Wavelength places AWS infrastructure within communications providers’ networks for edge applications that benefit from low-latency access from carrier networks. Exact millisecond values are design targets, not exam guarantees.
- AWS Outposts extends AWS-managed infrastructure and selected AWS services to customer premises for consistent hybrid operations, local processing, or residency requirements.
- AWS GovCloud (US) provides isolated Regions for eligible U.S. government and regulated workloads. Eligibility and U.S.-person access requirements are more nuanced than “any U.S. citizen can use it.”
- Data residency describes where data is stored. Data sovereignty concerns the legal jurisdiction governing that data. Compliance requirements define the obligations an organization must satisfy.

## Identity and access management

- Authentication verifies identity; authorization determines which actions that identity may perform.
- IAM users are identities within one AWS account and do not require their own billing method or external email address.
- A new IAM identity receives no permissions merely because it exists. Permissions must be granted through applicable policies and other authorization mechanisms.
- IAM policies are JSON documents. Common elements include `Effect`, `Action`, `Resource`, and optional `Condition` elements.
- Explicit deny overrides applicable allows. Least privilege means granting only the permissions required for the task.
- The AWS account root user has unrestricted account access. Enable MFA, do not create root access keys, and use root only for tasks that require it.
- For workforce access, temporary credentials and federation/IAM Identity Center are preferred over long-lived IAM-user access keys. An administrator IAM user with `AdministratorAccess` can be convenient in a disposable learning account but is not an example of least privilege.
- An IAM access key consists of an access key ID and secret access key. The secret is retrievable only when the key is created. An IAM user can have at most two access keys, enabling rotation without an abrupt cutover.
- Access key IDs are not secret in the same way as secret access keys, but neither credential should be exposed unnecessarily. Roles and temporary credentials are the preferred default for AWS workloads.
- Amazon Resource Names (ARNs) identify AWS resources using service-specific formats. ARN segments may be empty for global resources, and resource portions vary by service.

## Shared responsibility

- AWS is responsible for security **of** the cloud: facilities, hardware, foundational networking, and the virtualization layer.
- Customers are responsible for security **in** the cloud: their data, identities, permissions, application code, and service configurations.
- With Amazon EC2, the customer patches the guest operating system and applications and configures security groups; AWS manages physical infrastructure and the virtualization layer.
- Managed services shift more operational work to AWS, but customers always retain responsibilities such as data classification, access control, and secure configuration.
- With AWS Lambda, AWS manages the underlying infrastructure, operating system, and managed runtime platform. The customer remains responsible for function code and libraries, data, IAM, and resource configuration.

## Governance and compliance services

- AWS Organizations centrally groups accounts into an organization and organizational units.
- Service control policies (SCPs) define the maximum available permissions for principals in member accounts. They do not grant permissions and do not constrain principals in the management account.
- AWS Config records supported resource configurations and evaluates them against rules. Remediation is optional and must be explicitly configured; Config does not automatically terminate every noncompliant resource by itself.
- AWS Artifact provides on-demand access to AWS compliance reports and selected agreements. Artifact was only suggested in the earlier demo, not covered in the seven source reports, so it remains outside this day’s generated cards.

## Storage

- Amazon S3 is regional object storage. Data is stored as objects in buckets and accessed through APIs. Prefixes can create a folder-like presentation, but S3 is not a traditional mounted hierarchy.
- Amazon EBS provides durable block volumes for EC2. Volumes and attached instances must be in the same AZ. EBS normally attaches to one instance, but supported Provisioned IOPS volumes can use Multi-Attach with multiple Nitro-based instances in the same AZ.
- Amazon EFS provides elastic shared file storage using NFS and can be mounted by multiple compute instances. SMB is associated with alternatives such as Amazon FSx for Windows File Server, not EFS.
- Selection cue: object/API access → S3; EC2 block device or boot volume → EBS; shared Linux file system → EFS.
- EBS persists independently of an instance’s running life, but delete-on-termination settings can remove a volume when an instance terminates.
- S3 storage classes and detailed lifecycle selection were not studied deeply and remain a proposed gap.
- CloudShell’s standard environment provides 1 GB of persistent home-directory storage per supported Region. Data is removed after 120 days without launching CloudShell in that Region. CloudShell VPC environments do not provide this persistent home storage.

## Databases

- Amazon RDS manages relational database engines and operational tasks such as infrastructure provisioning and some patching/backup functions.
- DynamoDB is a managed NoSQL key-value and document database. It was mentioned in the context of gateway endpoints and SimpleDB, but its data model and capacity modes were not studied.
- Database service selection beyond RDS basics was not covered deeply enough for cards.

## Monitoring, messaging, and cost controls

- Amazon CloudWatch collects metrics and logs, displays dashboards, and creates alarms. Standard EC2 metrics include CPU and infrastructure metrics; guest-memory metrics require an agent or custom metrics.
- A CloudWatch alarm can notify an SNS topic or participate in automated actions. CloudWatch is operational monitoring; it is not the same as billing-threshold monitoring.
- Amazon SNS uses topics and subscriptions for publish/subscribe fan-out. Amazon SQS provides queues for decoupled processing.
- AWS Budgets tracks cost or usage against thresholds and can alert on actual or forecast values. A budget does not act as a hard spending cap by default; optional budget actions can be configured.
- AWS Cost Explorer is used to analyze and visualize cost and usage trends. AWS Budgets is used to watch thresholds and notify or trigger configured actions.
- Exact AWS Budgets pricing was omitted from cards because it can change and is not a durable conceptual objective.

## Compute, containers, and deployment services

- Amazon EC2 provides virtual machines. EC2 bare metal instance types provide direct access to underlying server hardware while retaining AWS service integration.
- The AWS Nitro System uses dedicated hardware and a lightweight hypervisor architecture to offload and isolate many virtualization functions. It reduces virtualization overhead; claims of literally zero overhead or exactly 100% guest CPU are too absolute.
- A cluster is a logical grouping or capacity boundary, not itself an orchestrator. ECS and EKS orchestrate workloads; EC2 Auto Scaling manages EC2 capacity; Elastic Load Balancing distributes network traffic.
- Amazon ECS is AWS container orchestration. Amazon EKS provides managed Kubernetes. AWS Fargate supplies serverless compute capacity for supported ECS and EKS workloads. Amazon ECR stores container images.
- Bottlerocket is an AWS-sponsored, minimal Linux-based operating system designed for hosting containers with an emphasis on security and transactional updates.
- AWS Elastic Beanstalk deploys web applications while provisioning and managing supporting AWS resources. There is no additional Beanstalk service charge, but underlying resources are billed.
- Amazon Lightsail bundles simplified virtual servers, storage, networking, and predictable plans for smaller or simpler workloads.
- AWS Batch plans, schedules, and runs batch workloads on supported compute environments. It can use Spot capacity for interrupt-tolerant work.
- AWS Compute Optimizer analyzes utilization and configuration data to recommend rightsizing and resource options; recommendations do not resize resources automatically.

## High-performance computing

- AWS ParallelCluster is an open-source cluster-management tool that automates creation and operation of HPC environments on AWS.
- A ParallelCluster head node coordinates the cluster. An EC2 key pair can provide administrative SSH access to the head node; the key pair is not the mechanism by which worker nodes identify one another.
- Cluster placement groups place supported EC2 instances close together within one AZ to reduce network latency.
- Elastic Fabric Adapter supports high-performance inter-instance communication for tightly coupled workloads.
- Amazon FSx for Lustre provides a high-performance parallel file system commonly used with HPC workloads.
- AWS Ground Station provides managed satellite ground-station capabilities and direct integration with AWS services.

## Pricing models studied

- On-Demand Instances require no long-term commitment and suit short-term, irregular, or non-interruptible workloads.
- Spot Instances use spare EC2 capacity at steep discounts but can be interrupted; they suit flexible and fault-tolerant workloads.
- Savings Plans exchange a one- or three-year consistent hourly spend commitment for discounted eligible compute usage. They are more flexible than EC2 Reserved Instances.
- Reserved Instances are a billing discount, not separate physical instances. Attributes and scope determine which usage receives the discount; zonal RIs can also provide a capacity-reservation benefit.
- Percentage discounts are intentionally not memorized as fixed facts because offers and exact conditions can change.

## High availability, fault tolerance, and disaster recovery

- High availability designs minimize downtime through redundancy and recovery. It does not correspond to one universal percentage such as 99.9%.
- Fault tolerance aims to continue operating despite component failure, usually through redundant components and automatic failover. “100% availability” is an aspiration, not a generally guaranteed property.
- Recovery Time Objective (RTO) is the maximum acceptable time to restore service after disruption.
- Recovery Point Objective (RPO) is the maximum acceptable amount of data loss measured in time before disruption.
- Backup and restore is generally the least expensive and slowest of the four studied DR approaches.
- Pilot light keeps the critical core of a workload ready in the recovery Region, including replicated data, while additional application infrastructure is deployed or started for recovery.
- Warm standby keeps a scaled-down but functional copy of the workload running in the recovery Region, enabling faster recovery at higher ongoing cost than pilot light.
- Multi-site active/active serves traffic from multiple Regions and is the most complex and costly approach. It can reduce recovery time to near zero, but RPO depends on the data architecture; active/active does not automatically guarantee synchronous global replication or zero data loss.
- Synchronous replication can target RPO 0 but adds latency and has technology and distance constraints. Asynchronous replication can leave a replication lag. Scheduled backups create an RPO based on backup frequency.
- DR strategies must be tested. The correct choice balances business impact, recovery objectives, complexity, and cost.

## APIs, endpoints, and infrastructure as code

- AWS service APIs use HTTPS endpoints. The Console, CLI, and SDKs abstract these requests.
- AWS Signature Version 4 signs supported API requests with credentials and request data so AWS can authenticate the caller and verify integrity. Invalid signatures can produce authorization errors; the response is not universally one exact `403 Unauthorized` message.
- Many services provide Regional endpoints. A few services are global or expose global endpoint behavior. Endpoint choice and service resource scope are related but not identical concepts.
- CloudFormation defines AWS resources in JSON or YAML templates and manages deployed resources as stacks.
- A stack is a collection of resources managed as a unit. Creation failures normally trigger rollback, but behavior depends on operation settings and resource behavior.
- Deleting a stack normally deletes its managed resources, but `DeletionPolicy`, retained resources, dependencies, or deletion failures can leave resources behind.
- AWS CDK lets developers define infrastructure with general-purpose languages and constructs, then synthesizes CloudFormation templates. Calling CDK purely “imperative IaC” hides the important fact that CloudFormation receives a declarative result.
- AWS SDKs are language-specific libraries for invoking AWS APIs from applications and automation. The CDK is for defining infrastructure; an SDK is commonly used for runtime operations against AWS services.

## Corrected misconceptions worth reviewing

1. A public subnet does not automatically make every resource public; routing, addressing, and security rules all matter.
2. S3 buckets are Regional resources outside customer subnets, despite globally unique names and a global console view.
3. Security groups are stateful and allow-only; NACLs are stateless and support allow and deny.
4. EC2 boot time changes RTO, not RPO.
5. Active/active does not by itself prove RPO 0.
6. Gateway endpoints support S3 and DynamoDB, but those services can also support interface endpoints.
7. SCPs limit maximum permissions; they do not grant access.
8. CloudFormation stack deletion is subject to deletion policies and possible failures.
9. EBS is normally single-instance block storage, with a constrained Multi-Attach exception.
10. EFS uses NFS, not SMB.
11. CDK synthesizes CloudFormation; it does not replace CloudFormation’s deployment engine.
12. Long-lived access keys are not the preferred default when temporary credentials or roles are available.
