# UI research: Anki-inspired study experience

## References reviewed

- [Anki manual — Studying](https://docs.ankiweb.net/studying.html)
- [Anki manual — Preferences](https://docs.ankiweb.net/preferences.html)
- [Anki manual — Card generation](https://docs.ankiweb.net/templates/generation.html)

## Patterns retained

- A deck overview separates New, Learning, and Review counts.
- The reviewer shows the question before the answer and keeps the question visible after reveal.
- Space or Enter reveals the answer; keys 1–4 select Again, Hard, Good, and Easy.
- Each rating displays its next interval before selection.
- Editing and secondary actions remain visually subordinate to the recall task.
- Review is utilitarian: neutral surfaces, compact navigation, strong text hierarchy, and limited semantic color.

## Hybrid desktop/mobile adaptation

- Desktop keeps a compact top navigation and keyboard-first reviewer.
- Mobile uses a bottom navigation and full-width rating controls sized for touch.
- The card is a flat content surface, not a decorative floating paper card.
- The Browser uses a dense list/detail layout on desktop and a stacked layout on mobile.

## Anti-vibecoding guardrails

- No gradients, glass effects, neon, decorative illustrations, oversized marketing copy, or emoji icons.
- No grid of interchangeable dashboard tiles; use tables and task-specific panels.
- Use one system font stack, 4–6 px radii, restrained borders, and shadows only for transient overlays.
- Use color only for meaning: New, Learning, Review, errors, success, and focus.
